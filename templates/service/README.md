# {{PKG_NAME}}

> A DeepSeek Harness **capability seam** (Service Definition + provider), generated by [`create-deepseek-harness-plugin`](https://www.npmjs.com/package/create-deepseek-harness-plugin).

Publishes `ctx.{{PLUGIN_ID_CAMEL}}` — a note store any other plugin can inject.

## The three roles

| Role | File | Answers |
|---|---|---|
| Service Definition | `src/index.ts` | WHAT the capability does (`{{SERVICE_CLASS}}`, abstract) |
| Service Provider | `src/local.ts` | HOW it does it (in-memory here — swap the marked lines) |
| Consumer | any plugin | `inject = ['{{PLUGIN_ID_CAMEL}}']`, then call it |

Only the provider is a loadable row; the Definition is imported for types and subclassed.
A mature seam splits these into separate packages so third parties can ship alternative
providers — they sit together here so the generated project runs immediately.

## Quick start

```sh
pnpm install
pnpm run build

# From the PARENT directory:
dsh plugin --profile my-profile add ./{{PKG_NAME}}
dsh --profile my-profile     # watch for: [{{PLUGIN_ID}}] provider ready — ctx.{{PLUGIN_ID_CAMEL}} available
```

## Consuming it from another plugin

```ts
export const inject = ['{{PLUGIN_ID_CAMEL}}']

export async function apply(ctx: Context) {
  await ctx.{{PLUGIN_ID_CAMEL}}.save('greeting', 'Hello, World!')
  const note = await ctx.{{PLUGIN_ID_CAMEL}}.load('greeting')
  console.log(note?.text)
}
```

`inject` is what makes load order correct: the consumer waits until this provider is up.
Loading a SECOND implementation of the same service throws — that is cordis' standard
duplicate-service behavior, not a bug.
