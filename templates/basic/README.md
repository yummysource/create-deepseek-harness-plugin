# {{PKG_NAME}}

> A DeepSeek Harness **side-effect plugin** with a configuration schema, generated by [`create-deepseek-harness-plugin`](https://www.npmjs.com/package/create-deepseek-harness-plugin).

Prints `Hello, World!` every 5 seconds. Both the message and the interval are configurable.

## Quick start

```sh
pnpm install
pnpm run build                 # tsc → dist/index.js (pure ESM)

# From the PARENT directory, install into a profile and boot:
dsh plugin --profile my-profile add ./{{PKG_NAME}}
dsh --profile my-profile       # watch for: [{{PLUGIN_ID}}] loaded — printing every 5000ms
```

> `dsh plugin add <dir>` anchors relative paths to the invoking directory — run it from the plugin's parent directory.

## Configure

The schema defaults ship as 5000 ms and `Hello, World!`. A user overrides them from
their own profile layer at `$DSH_HOME/profiles/<name>/cordis.patch.yml`, which applies
after every bundle layer — no change to this package required:

```yaml
- id: {{PLUGIN_ID}}
  config:
    interval: 10000
    message: Good morning
```

A patch **replaces** the whole `config` rather than merging keys, so restate every key the row needs.

## Dependencies pinned

Every `@deepseek-ai/*` package sits in `devDependencies` because it is **build-time types only**:
at runtime the plugin binds to the copies inside the running harness, resolved through
`$DSH_HOME/profiles/node_modules`. Declaring them as real dependencies would install a second copy.
