# {{PKG_NAME}}

> A DeepSeek Harness **observer plugin**, generated by [`create-deepseek-harness-plugin`](https://www.npmjs.com/package/create-deepseek-harness-plugin).

Listens to the session log, the tool registry, and the tool execution pipeline. It contributes
nothing — which makes it the right shape for telemetry, auditing, and mirroring state elsewhere.

## Two listener kinds, and why it matters

| Kind | Event here | Rule |
|---|---|---|
| emit | `session/event`, `tools/change` | A notification. Nobody is waiting on your return value. |
| waterfall | `tools/pre-execute` | A chain. **You MUST call `next()`** to delegate. |

Returning from a waterfall listener without calling `next()` short-circuits the chain — for
`tools/pre-execute` the tool call simply never happens, with no error anywhere. That silent
failure is the single most expensive mistake in this file's territory.

An observer always delegates. Returning a decision instead is how a *policy* plugin denies a
call — a different job, and one that belongs in its own plugin.

## Quick start

```sh
pnpm install
pnpm run build

# From the PARENT directory:
dsh plugin --profile my-profile add ./{{PKG_NAME}}
dsh --profile my-profile      # [{{PLUGIN_ID}}] listening: session/event, tools/change, tools/pre-execute
```

Session and tool events only fire once work actually runs, so drive a task to see them.

## Disposal

`ctx.on()` is already an effect — cordis removes those listeners on unload. The interval is a
resource cordis does not own, so it lives inside `ctx.effect()` with a disposer. Reload the
plugin and watch `DISPOSED` print before the new instance starts; that line is the proof the
plugin leaks nothing.

## Configure

```yaml
- id: {{PLUGIN_ID}}
  config:
    sampleEvery: 1     # log every session event instead of every 25th
```
